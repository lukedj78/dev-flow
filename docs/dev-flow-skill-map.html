Two families, two questions. The lint checks ask whether a skill is still well-formed — the twelfth compares what is installed against what is in this repo, because the two silently drifted: a real run found 25 of 43 installed skills carrying the previous day's text, the lint passed, the skills fired, and every one of them was the wrong version. The output checks ask a different question — did the generation follow its own rules? Every anti-slop rule and mandatory step was a promise about generated code that nothing counted. Both families are self-tested: a check nobody has watched fail is indistinguishable from a clean run.

04 installation

How to install them

Two ways in, two philosophies. The plugin subscribes you to the suite as a managed bundle that updates when we ship. install.sh copies editable files you can fork — and it's the route for Codex · Copilot · Gemini · Cursor.

Claude Code plugin — recommended
›/plugin marketplace add lukedj78/dev-flow
›/plugin install dev-flow@dev-flow

All 44 arrive namespaced (dev-flow:forms, dev-flow:rn-bootstrap…) and /plugin marketplace update pulls new releases. The shipped set is generated from the taxonomy, so it can't drift from skills.json — and both manifests pass claude plugin validate --strict.

B install.sh

Editable copies. Five runtimes, with the right bootstrap file and .bak backups.

$./install.sh --platform codex

Via GitHub CLI — all of it or a subset.

$gh skill install lukedj78/dev-flow

06 the rules

What every skill is held to

Three rules that apply before any skill does its job — one about how the skills are written, two about how the code they produce looks.
Eleven lint checks hold the suite to them, and three of those exist because the same thing kept happening: the content held and the metadata rotted. A capability documented in a body but missing from its description never loads. A skill absent from the README index is invisible. A count written in prose drifts the moment a skill is added.

0 Never invent

The skills are a doc-grounded second brain. No guessed API, flag or command: a “use library X” without the how from X's official docs is an incomplete skill. Prefer the version-matched source the tool itself ships — next dev maintains an AGENTS.md block pointing at the bundled docs; eve ships node_modules/eve/docs. Moving surfaces carry [VERIFY]; upstreams get re-checked on a cadence.

docs/knowledge-index.md → every how-to
1 English code

Identifiers, constants, types, columns, comments — always English, independent of the language you're speaking. Only user-facing copy is localized.

getUserById() not prendiUtente()
2 i18n on day one

Every frontend ships i18n from the scaffold — no hardcoded copy. Web next-intl, mobile the RN stack. Minimum en + it; adding it later touches every screen.

stack.locales = ["en", "it"]

That principle is why verification keeps paying. Real catches, before any of it reached a project: a CLI command we asserted in five places that had been removed upstream · an i18n API deprecated the same day we swept · a test library that turned its whole API async, silently breaking every test we generate on a fresh install · a default runtime that stopped working on iOS · a utility class that doesn't exist in the package we recommended.

And the inverse is a result too: this sweep confirmed two standing warnings were still correct, and that nine dependencies hadn't moved at all.

Ecosystem-first defaults

When a project needs one of these, we reach for the default rather than hand-roll — and each ships a doc-grounded how-to, never just a name. 13 of them so far.

i18n next-intl · web · i18next + expo-localization · mobile — minimum en + it
url state nuqs # the write side of the searchParams rung
storage Vercel Blob # same platform as the deploy, one less sub-processor
maps mapcn · web · mapcn-rn · mobile — mind the tile licence
motion tw-animate-css → CSS → view transitions → Motion # cheapest tier that works
illustration Koboyo # sparingly — only if DESIGN.md admits hand-drawn art

A default is a starting point, not an obligation: a project overrides any of them with a documented reason — and the ones it doesn't need stay null.
