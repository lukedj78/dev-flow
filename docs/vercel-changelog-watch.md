## How to run a watch pass

0. **Always check <https://nextjs.org/blog> first, for the security release.** Since 2026-07-13 Next.js publishes a **pre-announced security release roughly monthly**, each naming the highest anticipated severity. This is the one item on this page with a deadline: a missed feature is a missed feature, a missed patch is a live CVE. Record the current floor in `dev-flow/references/contracts.md` § `nextjs_version` and re-vendor. Two lines are maintained and **the labels move between releases** — read them off the release post every time, never from memory. (July: 16.2 Active LTS. August: **16.3** Active LTS, 16.2 no longer patched.) So neither "upgrade to latest" nor "stay on your line" is safe as a standing instruction: check which line is still receiving patches, then move to its current patch.
1. Fetch <https://vercel.com/changelog> — read the newest entries since the last dated pass below.

   ⚠️ The changelog renders dates as "11 August" with **no year**, and a summarising fetch will happily invent one — a pass in this repo got August 2026 entries returned as 2024. Cross-check the year against a second source before dating a log row.
2. For each entry, classify: **relevant** (touches a skill above) vs **not relevant** (a model id, an unrelated product).
3. For relevant items, edit the affected skill (mark new/unstable API `[VERIFY]` against the installed docs — eve is beta), and add a row to the log below with status `applied`.

   ⚠️ **For a default, a limit, a version floor or anything about what leaves the machine, verify against the shipped artefact and not the page.** `npm pack <pkg>@<version>` needs no install and carries the compiled `dist`, the `.d.ts`, `engines`, `peerDependencies`, the `exports` map and usually the `CHANGELOG` and `docs/`. The page states the intent, the `dist` states the behaviour. This page has the receipt: the 10-04 Agent Runs row is a correction to the 10-03 one, because *"preview and production deployments export by default"* read as a data egress and the content ceiling that made it metadata-only was a clause in a type comment. **A wrong row here propagates into a compliance checklist**, which is the one place a false positive costs more than silence. Where the range matters, `npm pack` across versions is the only thing that answers it — no page is written about the past.
4. Update the "Last pass" date. For anything ambiguous or out of scope, ask the user.
